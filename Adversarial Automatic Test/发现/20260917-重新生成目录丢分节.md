# 发现 2026-09-17-1：勾「重新为文档生成」目录，会把分节整个弄丢

> 来源：`aat_scan.py` 全量单因素扫描（397 个开关，夹具 `reference\民总.docx`，
> 预设 `中国政法大学-本科毕业论文.json`）。
> **本文件夹不修改生产代码**，这里只记录线索与证据，修复由用户/其它 Agent 决定。

## 一句话

结构页上勾选「重新为文档生成」目录之后，成品**从 2 节变成 1 节**：前置部分
（摘要/目录）的**罗马页码没了**，两套页眉也退化成一节共用，而且**没有任何告警**。

## 复现

```powershell
.venv\Scripts\python.exe "Adversarial Automatic Test\_probe_regen_section.py"
```

脚本做的事：同一份源文件、同一预设跑两遍，唯一差别是第二遍传
`ManualStructure.regenerate_fields = {"目录"}`（＝结构页上勾选那一个复选框）。

## 证据（脚本原样输出）

```
夹具：民总.docx    预设：中国政法大学-本科毕业论文.json

===== 基线：不勾「重新为文档生成」 =====
  民总.docx：116 段、2 节
  ▸ 段34 挂分节符  pgNumType.fmt='upperRoman'  文字=''
  ▸ body 末尾 sectPr  pgNumType.fmt='decimal'
     节0: 页眉(链接前节=False) 页脚(链接前节=False) 左=2.00cm 下=2.50cm
     节1: 页眉(链接前节=False) 页脚(链接前节=False) 左=2.00cm 下=2.50cm

===== 实验：勾上「重新为文档生成」目录 =====
  民总.docx：97 段、1 节
  ▸ body 末尾 sectPr  pgNumType.fmt='decimal'
     节0: 页眉(链接前节=False) 页脚(链接前节=False) 左=2.00cm 下=2.50cm
```

要点：
- **没有任何段落挂分节符**了（基线是段34 挂着的 `upperRoman`）；
- 段数 116 → 97，少了 19 段，正是旧目录的条目数；
- 前置部分本应 `upperRoman`（罗马页码），现在整篇只剩 `decimal`。

## 机制推测（未逐行验证，供修复时参考）

`pipeline.run()` 里的顺序是：

1. 取 `body_anchor`（正文第一个已识别标题的**段落对象**，在插段落**之前**取）；
2. `split_body_section(document, body_anchor)` —— 在正文首个标题**之前**插入分节符；
3. 管线**最后**才 `drop_regenerated_fields(document, {"目录"}, keep=new_fields)`
   删掉源文件里那份旧目录（按 2026-09-15 的裁决，删除必须放到最后，否则下标平移）。

如果第 2 步把分节符写在了"正文首标题**前一段**"的 `w:pPr/w:sectPr` 上，而
那一段**恰好就是旧目录的最后一条条目**（民总的目录紧接着引言），那么第 3 步
删旧目录时就会把分节符**一起删掉**。

⇒ 两件事的次序对了（先分节后删目录），但**载体撞在了一起**。

## 影响

- 用户勾一下复选框，前置部分罗马页码 + 两套页眉（封面节除外）静默失效；
- **不报任何告警**，用户只能靠打开成品翻到目录页自己发现；
- 越靠文档后部的部件越不受影响，所以容易被忽略。

## 建议的验证与修法方向（不在此文件夹实施）

- 验证：`drop_regenerated_fields` 删段落之前，先记下"哪些段落挂着 `w:sectPr`"，
  删完之后比对；或者干脆断言"分节数不该变"。
- 修法方向（任选，按副作用小排）：
  1. `split_body_section` 把分节符放在**新插入的空段落**上，不要借用已有段落；
  2. 或者把 `split_body_section` 挪到 `drop_regenerated_fields` **之后**（那时旧目录
     已删干净，锚点段落也稳定）——但要重新确认下标口径；
  3. 或者在 `drop_regenerated_fields` 里"要删的段落带着 `w:sectPr` 时，先把
     分节符搬到旁边的段落上再删"。
- 回归：修完请用 `_probe_regen_section.py` 复核"节数 2 → 2"，并跑
  `tools\_check_regen_toc.py`、`tools\_check_mz_toc_and_center.py`（这两个已有脚本
  只断言"只剩 1 个 TOC 域、0 条旧条目"，**没有断言节数**，所以当初没抓到）。
