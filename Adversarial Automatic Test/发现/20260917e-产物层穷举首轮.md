## 五条不收敛（每遍都变）

| 夹具 | 搬运 | 段数 P1→P2→P3→P4 | 每遍多出来的是 |
|---|---|---|---|
| 民总 | 内容控件包住全部段落 | 128 → 130 → **135** | 题目、副标题占位 |
| 民总 | 域没闭合（删掉 `fldChar end`） | 120 → 124 → **128** | 参考文献 + 条目占位、致谢 + 致谢占位 |
| 图表脚注测试 | 域没闭合（删掉 `fldChar end`） | 90 → 94 → **98** | 同上（每遍 +4 段） |
| 图表脚注测试 | body 内容整体复制 | 159 → 160 → **161** | 英文副标题占位（每遍 +1 段） |
| 图表脚注测试 | 首段 run 包进未接受的修订 | 88 → 89 → **90** | 副标题占位（每遍 +1 段） |

**为什么这是错**：用户"导出 → 再拿产物导出一次"是很常见的动作。每导出一次文档
就长几段，导出的份数越多越离谱。历史上这一类已经修过一次（成品回炉 83→84），
所以这不是新类别，说明还有几条路径没堵上。

**机制（推测，未逐条落实到代码行）**：那条"认不出某部件 ⇒ 插占位文本"的补件逻辑，
在**识别看不到那一段**时每跑一遍就补一次，而补出来的占位又进入了下一轮的识别范围。
三个触发源分别是：段落被包进 `w:sdt`（`document.paragraphs` 看不见）、域没闭合
（后面的内容都被算进域里）、未接受的修订（内容被包在 `w:ins` 里）。
