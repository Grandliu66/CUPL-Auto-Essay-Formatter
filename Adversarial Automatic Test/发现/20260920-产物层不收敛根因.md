## 一句话根因

**补件生成的占位语“落脚点”与识别端认占位语的“窗口”是两套口径，错开时每轮重新生成一条。**

- 落点（现状）＝索引法 ops：部件缺失 → `pending` → 倒在下个“已识别部件”之前
  （`doc_index.build_ops()` 的 `emit_missing()` → `emit_existing()`/收尾段里的
  `flush_before()+drain_pending()`）。
- 窗口（识别端）＝`detect.slot_after()`（题目下一段、可穿空段/占位语）+ 前向区
  （【摘要】/关键词/英文题名只在前向识别器扫过的那片里认）。

若占位语落不进窗口 → 下一轮又判“该部件缺失” → 再生成一条 → 产物每轮变长。

## 三类触发形状（均有盘上证据）

**A. 题目被封面行顶掉**（写作模板 段0「论文编号：（4号楷体）」、空白模板 段0「论文编号：」、
格式规范 段3「中国政法大学」）
→ 识别出的“题目”在封面里 ⇒ 副标题槽位也在封面里；而补件把副标题占位语排到
“下一个部件（【摘要】）之前”（写作模板 36 起、空白模板 34 起、格式规范 17 起）
⇒ 识别端只认“紧邻题目” ⇒ 每轮 +1 条，全堆在【摘要】前。

**B. 第一个标题在文档最前**（TitleIdentify 段0「一、一级标题1」）
→ 前向识别器地盘为空（前向扫描止于第一个标题形状段）⇒ 【摘要】【关键词】英文题名
整套判“缺失” ⇒ 每轮往“【目录】之前”插一套 10 段（55→65→75，p3/p4 里三、四套叠放）。

**C. 让“题目→副标题”链断掉的搬运**（PaperTest / 图表脚注测试 / 一般情景测试-排好版 的
「首段 run 包进未接受的修订」等）
→ 实测（`_probe_ins_title.py`）：段0 包 `w:ins` 后**段0 不再被认成题目、题目整体上移一位**
（段1 变题目），副标题环节错位 ⇒ 每轮 +1。
（「首段拉到 5000 字」「零宽字符」在个别夹具上同理触发；具体打中哪一步按现场逐个看。）

## 为什么是“回归”

- 2026-09-17 在旧路径修过一次并跑到全绿（372/372）：`detect.slot_after()` +
  `apply_missing_parts(subtitle_slots=…)`——**补件按题目槽位落点**，识别端认槽位里的占位语。
- 2026-09-19 起补件迁到索引法（“按索引顺序逐个往后追加”）。`emit_missing()` 只看
  “部件序 + 下个已识别部件”，**槽位机制没跟过去**：全库 grep，`slot_after` 只剩
  `detect.py:346` 一处定义、ops 路径零引用。识别端判据（`detect.py:1310/1329`
  的 `is_subtitle_placeholder`）还在。⇒ 两套口径从此分家，A/B/C 三种形状一碰就转不起来。

## 修复方向（二选一；原则＝落点口径与识别窗同一个定义）

- **甲（建议，改补件端）**：`build_ops()` 给“副标题/英文副标题”的 generate 指令**专用落点**——
  排在识别出的题目条目之后（`slot_after`）；“前向区部件（摘要/关键词/英文题名）”的
  generate 落点也放“题目之后、第一个标题之前”，而不是“下个已识别部件之前”。
- **乙（改识别端）**：前向区放宽到“题目之后、后向停止之前”，并认“题目与下一个已知部件
  之间的占位语”。两处口径都要动，代价大。

## 附带：`gen_pipeline.py` 自己一个小 bug

`raise SystemExit(main(sys.argv[1:]))` + `main` 内 `given = [... for name in argv[1:] ...]`
**双重切片** ⇒ 第一个位置参数被吞（实测：只给一个夹具名会静默回落到默认清单；
`A B C` 只跑 B、C）。要按夹具过滤时前面垫一个名字（如上面的 `民总.docx`），或修成
`argv[0:]`。
