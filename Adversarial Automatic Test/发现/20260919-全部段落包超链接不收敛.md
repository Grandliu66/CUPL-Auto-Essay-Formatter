# 发现：全部段落包进超链接 → 产物不收敛（每遍多一个空格）

> 2026-09-19，`gen_pipeline.py` 新增搬运「全部段落包进超链接」首轮扫出。
> 夹具：`民总.docx`、`图表脚注测试.docx` **两份都中**。

## 现象

```
.venv\Scripts\python.exe "Adversarial Automatic Test\gen_pipeline.py" --only 全部段落包进 --jobs 1 --keep
```

结论 `✘不收敛（每遍都变）`，逐遍对比（民总）：

```
P2[38]='（一）我国民法的民事行为能力与监护（一）  '
P3[38]='（一）我国民法的民事行为能力与监护（一）   '
P4[38]='（一）我国民法的民事行为能力与监护（一）    '   ← 每遍尾部多一个空格
```

（另一份夹具同型：`（一）二级标题（一）  ` → `   ` → `    `。）

## 与旧已知问题的关系

同族但**不同触发**：docs 交接文档 27.1 修过「空标题行编号后空格每回炉多一个」。
这次的触发条件是**段落被超链接包住**（`w:hyperlink` 里放 run）——说明归一化
补空格那一段的"是否已经补过"判据，在 run 被超链接包住时读/写落在了不同 run 上，
于是每一遍都再补一个。

## 影响与建议

- 用户可见：回炉一次屁股多一个空格；反复回炉会持续增长（不收敛）。
- 定位起点：`normalize_document` 里给中文编号补空格的那段（`（一）` 系），
  检查它对 `w:hyperlink` 包裹的 run 的处理；`apply_from_index` 侧的写入
  位置也要看是否与读取位置一致。
- 复现现场保留在 `_out/gen_pipeline/hyperlink/`（`--keep --tag hyperlink`）。
