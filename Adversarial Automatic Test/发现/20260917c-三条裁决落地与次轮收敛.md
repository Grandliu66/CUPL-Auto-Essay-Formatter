## 二、自动编号反算：自己写了一个模块（不借引擎）

`aat_expect.py` 里新增 `read_numbering()` / `format_number()` / `reverse_numbering()`：
直接读 `word/numbering.xml` 的 `abstractNum`（`w:start` / `w:numFmt` / `w:lvlText`）、
`w:num`、`w:lvlOverride`，按文档顺序维护"各级计数"，本级 +1、更深层级清零，
把 `%1`~`%9` 按各自 `numFmt` 填成可见文字。

**为什么不调 `essay_tool/engine/numbering.py`**：两边共用一份实现的话，同一个错
会同时出现在"期望"和"实际"里，差分就永远看不见它。

支持的编号格式：`decimal`、`chineseCounting`、`chineseCountingThousand`、
`lowerRoman`/`upperRoman`、`lowerLetter`/`upperLetter`、`decimalEnclosedCircle`、
`decimalEnclosedParen`、`decimalEnclosedFullstop`。

### 补：第 4 条的“页码尾巴”那一半又放行了（同日第三轮）

用户看了上面的梳理后说：**「末尾带省略号那个你可以用」**，并给了真正难的那种做法：

```
目录
一、111
二、222

xxx
一、111
1111111
二、222
2222222
```

并说“这似乎没招”。于是：

* **已写进表 R9**：例外列加「文档里手打的目录条目——末尾为省略号或制表符后接页码的那几行——不识别为标题」；
  样式应用规则列加「手打的目录条目不属于域生成的条目：重新生成目录时，落在目录域区间内的会随旧目录一起删掉；
  落在域区间外的会作为多余的正文保留下来，并触发 3.7 第 8 条告警」。
* **已实现**：`aat_expect.is_hand_toc_entry()`（`…{2,}|\.{3,}|\t` + 页码 + 结尾）。顺带发现读取器
  **把 `w:tab` 丢了**（只收 `w:t`）⇒ `aat_docx` 现在把制表符读成 `\t`，否则靠制表位拉页码的那种条目一条都认不出。
* **结果**：三个夹具（民总 / 图表脚注测试 / 压力测试_Agent版）全部 **0 差异**。
* **没招的那一半仍然是没招**：用户例子里的 `一、111`/`二、222` 没有页码尾巴，与正文里的同级标题
  **文字完全同形**，页面上也没有可用硬标记（同样式同格式）⇒ 没判据，两个侧（预估与引擎）都会
  把它认成一级标题，因此**差分看不到它**（两边一致地错）。这一条已登记进 `ASSUMPTIONS`。
